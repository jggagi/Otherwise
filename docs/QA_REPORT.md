`story_test.gd` 当前 530 项检查、0 失败；包含 18 基本结尾及每个分支的中断／重试和中断／普通出口。测试阶段损坏 JSON 曾产生引擎错误日志，已改为 `JSON.new().parse`，格式损坏被正常处理而不报脚本错误。

输入回归发现了以下真实问题并修复：片尾没有接收数字键重开；键盘移动靠近墙时落在网格离散单元边界，点击寻路无法找到起点。现在选择附近可达单元，角色实际走过去，不瞬移。暂停菜单的数字键也已修复；检查发圈后选择稍后确认，可以再次回来确认 Anchor，检查结果自动保存。

性能最初默认 VSync 采样为中位 31.303 ms／P95 32.131 ms。关闭 VSync 并限制 60 FPS 后，实测上表数据；已用同一配置作为默认值。引擎静态内存约 82 MB，渲染视频内存约 65 MB。它们不是整机进程工作集。该采样只覆盖短暂公寓稳态，不证明长时间、多机器、全部转场都稳定 60 FPS。

## 可复核入口

- `scripts/tests/story_test.gd`：状态、结尾矩阵、存档与真实移动。
- `scripts/tests/input_test.gd`：实际输入分发的一条完整普通结尾。
- `scripts/capture_story.gd`：状态驱动渲染；错误状态会失败。
- `scripts/tests/performance_test.gd`：帧间隔与引擎内存采样。
- `scripts/build-windows.ps1`：离线可重复 Windows 构建，拒绝覆盖已有版本。
- `.local/validation/`：此机器日志、渲染画面与测试用户目录，Git 忽略。
- `.local/build/`：导入／导出日志与沙盒内临时文件，Git 忽略。

## 发行包验证

最终包已解压验证：文件 SHA256 全部匹配；release EXE 通过最小 `--verify-boot` 入口正常启动和退出，实际加载主场景、玩家、音频和中文字体，无错误。官方 4.7.2 release 模板的 `--help` 未提供 `--script` / `--main-pack` 覆盖入口，因此包内剧情矩阵使用同版本 editor 引擎加载解压目录内 PCK，外部测试脚本只作为驱动。`--path` 指向解压目录，避免回退读取仓库源码；隔离探针确认开发脚本不存在，并确认全部新资源和标题页正常。

包内 18 条结尾矩阵、存档、中断与真实寻路通过；渲染模式的输入流程完成普通结尾和重开。它们验证发行内容，没有冒称原生 release EXE 的人工键鼠通关。流程可由 `scripts/verify-windows.ps1` 复现。Godot 对扩展 CLI 参数的限制参考[官方命令行说明](https://docs.godotengine.org/en/latest/tutorials/editor/command_line_tutorial.html)，本轮判断以实际已安装模板的 `--help` 为准。

第一次导出虽然退出码为 0，但临时目录写入失败；已将 TEMP/TMP 限定到仓库，重建并增加日志错误门槛。坏包已删除。`--quit-after` 的直接引擎退出曾暴露尚未排空的 rain WAV 回放；正常退出已停止音频并等待缓冲释放，最小启动入口也沿用这条关闭路径，不将强制退出误报为剧情错误。Godot 引擎／内含库与字体许可随包附带。最终 ZIP 与 SHA256 文件在 `releases/otherwise/`。本轮 ZIP SHA256：`9135f27c14e7bbf2a139944693dc7e7b63ae47c62c3ef1ded1ec8cf34ac17704`。
